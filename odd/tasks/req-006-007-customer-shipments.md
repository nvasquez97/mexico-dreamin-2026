## Findings
- REQ-006: the request form asks pickup address, city and postal code; pickup date; recipient name, address, city, postal code, phone and email; service type (Standard, Express); weight; description; declared value; optional order reference and delivery instructions; the price at the current rate (BR-08) is shown before confirming; the pickup date is a business day between the next day and 15 days later; maximum 30 kg and 50,000 MXN declared; on confirmation the shipment is created under the customer, Requested, with its tracking number shown; estimated delivery = pickup date + 5 business days (Standard) or + 2 (Express) (`docs/functional-design.md:141-150`).
- REQ-007: the list shows tracking number, request date, recipient, destination city, status, service type and price, most recent first; filter by status; search by tracking number, recipient or reference; a detail page with the entered data, the price and the current status (`docs/functional-design.md:152-158`).

- D5: sharing set on Account__c for customer users; Shipment__c external OWD Private (`force-app/main/default/objects/Shipment__c/Shipment__c.object-meta.xml:15`). - ShipmentTriggerHandler.beforeInsert forces Status Requested (AC-F.15) and fills Original_Estimated_Delivery__c from Estimated_Delivery__c; afterInsert issues the access code (`force-app/main/default/classes/ShipmentTriggerHandler.cls:22-53,89-91`). Name is an AutoNumber RC{000000000} (BR-05).
- Field types: Weight_Kg__c Number(8,2), Declared_Value__c and Price__c Currency(16,2), Pickup_Address__c and Recipient_Address__c LongTextArea(1000), Package_Description__c Text(255), Origin_City__c / Destination_City__c Text(80), Destination_Postal_Code__c Text(10), Customer_Reference__c Text(50), Delivery_Instructions__c LongTextArea(1000); Margin__c is a formula.

## Problems
- P1: Customers cannot request pickups online nor follow their shipments (evidence: REQ-006, REQ-007 stories).
- P2: If price, account, status or estimated date come from the client — or from a direct UI API create — a customer can set their own price, put a shipment under another account, or start it in another status (evidence: BR-08, BR-07, BR-09, X6).
- P3: A customer reading another customer's shipments, or any customer reading cost, margin, notes, the hash or credit fields, breaks BR-07 and BR-03 (evidence: BR-03, BR-07, P4, X11).
- P4: Wrong date arithmetic (server clock vs Mexico City, weekends) gives invalid pickup dates or wrong estimates (evidence: AC-006.3, AC-006.6, BR-06).
- P5: The quote shown before confirming may differ from the stored price if computed in two places (evidence: AC-006.2, BR-08).
- P6: Unbounded lists or a search built from client input could be slow or injectable (evidence: AC-007.2, P8, NFR under 2 seconds, 200,000 shipments a year).

## Solutions
- S1 → P2, P4, P5: one pricing and dates service `ShipmentRequestRules` (`with sharing`, pure functions): price = base + per-kg × weight + 1.5% × declared value, rounded half-up to 2 decimals (BR-08); business days = Monday–Friday (no holiday calendar, G1); "today" = the current date in America/Mexico_City (test seam); pickup date valid when it is a business day in [today+1, today+15]; estimate = pickup + 5 or + 2 business days; weight in (0, 30], declared value in [0, 50,000]. The SAME rules are enforced in ShipmentTriggerHandler.beforeInsert for every insert by a user of the profile "RutaCargo Customer": Account__c is overwritten with the user's Contact.AccountId, Price__c, Estimated_Delivery__c (and so Original_Estimated_Delivery__c) are computed, Status is Requested (existing), protected fields (Carrier_Cost__c, Internal_Notes__c, Proof_Id__c, Delivered_At__c, Last_*, Reschedule_Count__c, the hash) are cleared, and a rule violation adds a field error — so a direct UI API create obeys BR-07/08/09 exactly like the controller. Discarded: computing only in the controller (UI API bypass, X6); no Create permission plus a system-mode insert helper (keeps user mode out, needs a `without sharing` class for a non-guest actor); a holiday Custom Metadata list (no source for holidays in the design; G1).
- S2 → P3: access configuration for customers: RutaCargo_Customer gets Shipment__c Read and Create (no Edit, Delete, View All, Modify All); FLS read on the AC-007 list and detail fields (Name via record access, Status__c, Service_Type__c, Price__c, Estimated_Delivery__c, Pickup_*, Origin_City__c, Destination_City__c, Destination_Postal_Code__c, Recipient_Name__c, Recipient_Address__c, Recipient_Phone__c, Recipient_Email__c, Package_Description__c, Weight_Kg__c, Declared_Value__c, Customer_Reference__c, Delivery_Instructions__c, Last_Location__c, Last_Update__c, CreatedDate) and edit (create) FLS only on the AC-006.1 entered fields; nothing on Carrier_Cost__c, Margin__c, Internal_Notes__c, Delivery_Access_Code_Hash__c, Proof_Id__c, Account Credit_Limit__c / Credit_Risk__c. A sharing set "RutaCargo Customer Shipments" for the profile "RutaCargo Customer": Shipment__c where Account__c = User.Contact.AccountId, Read only. Account and Contact: no new grant (not needed by these pages; G2). Discarded: Customer Community Plus roles and sharing rules (license D5); View All (BR-07).
- S3 → P1, P2: `ShipmentRequestController` (`with sharing`, user mode, individual fields): `getQuote(serviceType, weightKg, declaredValue)` (cacheable=false; returns price and the allowed pickup date range), `submitRequest(…all AC-006.1 fields…)` validates with ShipmentRequestRules, inserts in user mode through `DeliveryAccessCode.insertWithCodes` and returns trackingNumber, price, estimatedDelivery and the clear access code (shown once, A1); errors as generic field messages; the price returned equals the stored one (same function). Discarded: deserializing a Shipment__c from the client (X6).
- S4 → P3, P6: `MyShipmentsController` (`with sharing`, user mode, cacheable=false): `listShipments(String status, String searchTerm)` with status from the closed picklist list (or blank), search term trimmed, ≤ 50 characters, escaped and bound (LIKE on Name, Recipient_Name__c, Customer_Reference__c), ORDER BY CreatedDate DESC, LIMIT 200 (G3), returning a DTO with the seven AC-007.1 fields (request date in Mexico City); `getShipment(String trackingNumber)` returns the AC-007.3 DTO for a shipment the user can read (user mode: another customer's number returns "not found", never an error that leaks existence). Discarded: dynamic sort fields (closed list not needed: one fixed order); Id-based detail URLs (tracking number is the customer's key).
- S5 → P1: LWCs `rcRequestShipment` (form, live quote, confirmation with tracking number, estimate and access code), `rcMyShipments` (list with status filter and search, mobile cards) and `rcShipmentDetail`, on new LWR routes "request-shipment", "my-shipments" and "shipment-detail" (?tracking=RC…), each requiring login (guests are redirected to the login page); header links for logged-in customers. Jest with Sa11y; brand palette.
