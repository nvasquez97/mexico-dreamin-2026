## Problems
- P1: Without the objects and fields, no requirement can be built or tested; a wrong picklist value would silently break the EntregaYa contract, which sends the status label as text (evidence: data model table, REQ-004 body example "Out for delivery").
- P2: Tracking numbers that are not consecutive or not in the RC + 9 digits format break BR-05; Apex tests and stray inserts consume the Auto Number sequence, so the design's test data (RC000001001–1120) becomes unreproducible (evidence: BR-05, test data table).
- P3: An internal or external sharing model wider than Private on Shipment__c or Account would let users who do not need them (the EntregaYa integration user, other internal users, customers, guests) read recipients' personal data or credit data (evidence: BR-02, BR-03, BR-07; policy P3).
- P4: The recipient must not be authorized only by a guessable tracking number and a public postal code (policy X16); a secret per shipment must exist from creation, on every path that creates shipments, must be generated with secure randomness (X8), must not be readable from the database in clear (owner decision D1: stored hashed), and must not be overwritten by later code (evidence: D1 in .mem/memory.md).
- P5: Reschedules must be bounded by the first estimate, which is lost once Estimated_Delivery__c is changed, or never captured when the shipment is created without an estimate (evidence: AC-003.2, owner decision D4).
- P6: Support agents need the internal fields; any wider grant (Delete, View All, Modify All, edit on system-computed fields) breaks least privilege and BR-09 (evidence: BR-03, BR-09, policy on minimal permission sets).
- P7: A site created by clicks is not versioned and cannot be rebuilt in the next scratch org; a guest profile with object permissions exposes data directly through the APIs; an unpublished site serves nothing (evidence: policy "The guest user receives no object permissions", X11).
- P8: Dates rendered in the org or browser time zone break BR-06 for visitors and seeded timestamps.
- P9: Test data loaded by hand is not reproducible and the definition of done requires a script (evidence: DoD "test data loaded with a reproducible script").
- P10: The public search by order reference is a full scan without an index and misses the 2-second target at volume (evidence: REQ-001, NFR response time).

## Solutions
- S1 → P1, P2, P3, P10: Account fields and Shipment__c with every design field, plus Original_Estimated_Delivery__c (Date) and Delivery_Access_Code_Hash__c (Text 100, salt and hash); Name is an Auto Number `RC{000000000}` starting at 1001; picklist API names equal the design labels; Status__c defaults to Requested (BR-09); Account__c is a required lookup with delete Restrict; Customer_Reference__c is an External ID (not unique) so it is indexed; Shipment__c internal and external sharing Private; Account internal and external sharing Private (Contact controlled by parent); field history on Status__c, Estimated_Delivery__c and Delivery_Instructions__c; Apex settings with the independent test Auto Number sequence enabled (mandatory). Discarded: a Text Name filled by a trigger from a counter record (row-lock contention at peak and a home-grown sequence); master-detail to Account (would force sharing to follow Account and block reparenting); keeping internal Read/Write (no written P3 justification: the integration user is internal and must not see every shipment's PII).
- S2 → P4, P5: one Shipment__c trigger with a handler. Before insert: generate a 10-character code with `Crypto.getRandomInteger` and rejection sampling over the alphabet `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (overwriting any value the caller sent), store only a random salt and the SHA-256 of salt + code in Delivery_Access_Code_Hash__c, and keep the clear codes for the current transaction only in a static list aligned with Trigger.new, so the creating code can show it once (REQ-006 confirmation, seed output); copy Estimated_Delivery__c into Original_Estimated_Delivery__c. Before update: revert any change to Delivery_Access_Code_Hash__c, and to Original_Estimated_Delivery__c once it is filled; fill Original_Estimated_Delivery__c when it is blank and Estimated_Delivery__c is set. A `DeliveryAccessCode.matches(shipment, code)` helper compares in constant time for REQ-002. Discarded: storing the code in clear with FLS (reverses owner decision D1; anyone with the field or system-mode code can read every secret); generating the code in each controller (a path that forgets it leaves a shipment without a secret).
- S3 → P3, P6: permission set RutaCargo_Support_Agent: Shipment__c Read, Create, Edit (no Delete, View All, Modify All); read on every Shipment__c field except Delivery_Access_Code_Hash__c (no access), edit on every field except Name, Margin__c, Original_Estimated_Delivery__c and Delivery_Access_Code_Hash__c; read and edit on the three Account fields; the Shipment tab and a RutaCargo Lightning app. Visibility comes from a public group RutaCargo_Support_Agents and criteria-based sharing rules giving the group Read/Write on all shipments and on customer accounts (Customer_Type__c set). Discarded: View All / Modify All in the permission set (policy flags them); a cloned profile (profiles are being retired for permissions).
- S4 → P7, P8: an LWR Experience Cloud site "RutaCargo" (URL prefix `rutacargo`), created, published (Network Status Live) and retrieved into force-app so it is versioned; its guest profile `RutaCargo Profile` with no object permissions at all; the guest user's time zone set to America/Mexico_City by a versioned setup script (the user record is data, not metadata). Discarded: Aura template (older runtime, slower on mobile).
- S5 → P7: brand theme for the site: palette, Montserrat self-hosted in a static resource, logos in a static resource each used on its own background, a header component with the logo and a public home page placeholder; scripts/checks/brand-check.sh asserts the wiring. Discarded: loading Montserrat from Google Fonts at runtime (needs a CSP trusted site to an external host); Daily Brew (no font file in the repo: headings fall back to Montserrat Black in uppercase, assumption A3).
- S6 → P8, P9: an idempotent seed script under scripts/seed/ (shell wrapper around anonymous Apex) that fails fast unless the next tracking number is RC000001001 on a first load, inserts Acme's 60 shipments and then Globex's 60 in one ordered DML, sets dates relative to the run date in America/Mexico_City, and writes the clear access codes of the seeded shipments only to a git-ignored local file (.seed-output/); a verify script asserts the counts, tracking numbers, statuses and Delivered data; the README gets the run steps and the run's assumptions. Site users for Ana López and Marta Ruiz are added by REQ-005. Discarded: `sf data tree import` JSON files (cannot compute relative dates, cannot assert).
