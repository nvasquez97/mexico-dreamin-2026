## Findings
- REQ-001 asks for search by tracking number or by order reference, up to 10 values separated by commas or line breaks, case and surrounding spaces ignored, "Not found" for values with no match, sorting by status or estimated delivery date (`docs/functional-design.md:91-99`).
- BR-01: the public information of a shipment is exactly the AC-001.2 list (tracking number, status, origin city, destination city, last location, last update, estimated delivery) and nothing else; BR-03: price, cost, margin, notes are never shown to visitors; BR-06: dates in Mexico City time (`docs/functional-design.md:166-171`).
- Shipment__c is Private internally and externally (foundation S1, A2); the guest profile "RutaCargo Profile" has 0 object permissions and 0 Shipment__c FLS, guarded by `scripts/checks/guest-access-check.sh` (sections 3, 3b); the guest profile has no Apex class access today (`force-app/main/default/profiles/RutaCargo Profile.profile-meta.xml`, no classAccesses).
- Project policy: "The guest user receives no object permissions" (CLAUDE.md); P1: every `@AuraEnabled` method in a guest-accessible class is callable anonymously; P11: `without sharing` only in small isolated helpers with a justification, never on an entry-point class; A7: SECURITY-JUSTIFICATION approver is "pending owner approval".
- Tracking numbers are the Name, `^RC\d{9}$`, consecutive (BR-05, foundation AC-F.2); Customer_Reference__c is Text(50), External ID (indexed), not unique (`force-app/main/default/objects/Shipment__c/fields/Customer_Reference__c.field-meta.xml`), so one reference may match several shipments, possibly of different customers.
- Status__c picklist order is the lifecycle: Requested, Picked up, In transit, Out for delivery, Delivered, Exception (`force-app/main/default/objects/Shipment__c/fields/Status__c.field-meta.xml`).
- Network enableApexCDNCaching is true: guest `cacheable=true` Apex results can be cached by the CDN (foundation Close, pre-existing notes).
- The home page view places `c:rcHome`, a placeholder hero with no data (`force-app/main/default/digitalExperiences/site/RutaCargo1/sfdc_cms__view/home/content.json:23`, `force-app/main/default/lwc/rcHome/rcHome.html`); the theme layout wraps `c:rcHeader` in `community_byo:scopedHeaderAndFooter` (`force-app/main/default/digitalExperiences/site/RutaCargo1/sfdc_cms__themeLayout/scopedHeaderAndFooter/content.json:28,75`).
- Carried from the foundation Close (brand-reviewer, open): [High] the full logo renders about 303 px wide at 1366 px (logo-negative.png has ~8% crop margin; needs ≥430 px image width and a higher breakpoint); [Medium] the #EFF0F2 gray wrapper of community_byo:scopedHeaderAndFooter is still visible around header and footer (`odd/tasks/archive/2026-11-17-foundation.md`, Close).
- Site styles.css never publishes in this org; Montserrat is loaded through loadStyle in rcHeader (foundation T5); `scripts/checks/brand-check.sh` checks the palette, logos and font.
- Tests can run as the real site guest user (User records are visible to tests without SeeAllData; profile "RutaCargo Profile").

## Problems
- P1: Visitors cannot see where their package is without calling the contact center (evidence: REQ-001 story, ~1,200 calls a day).
- P2: Giving the guest Read on Shipment__c (object permission or guest sharing rule) would expose every readable field through the UI API and Aura endpoints, not only BR-01's list (evidence: BR-01, BR-03, P1, project rule "guest receives no object permissions").
- P3: A system-mode read reachable anonymously could leak private fields (recipient, price, cost, notes) if the query or the response object grows, or be abused with injected search fields or unbounded result sets (evidence: BR-01, BR-03, P8, P10, X7).
- P4: Sequential tracking numbers let anyone enumerate the public data of every shipment; BR-01 accepts this for the AC-001.2 fields, but anything beyond them, or error messages that differ by record state, turns enumeration into a leak (evidence: BR-05, X16).
- P5: The CDN may cache a guest `cacheable=true` response, serving stale statuses (evidence: enableApexCDNCaching true).
- P6: The two open brand findings make the site's header off-brand on desktop (evidence: foundation Close, brand-reviewer).

## Solutions
- S1 → P2, P3, P4, P5: an entry-point class `PublicTrackingController` (`with sharing`) with one non-cacheable `@AuraEnabled` method `search(String mode, List<String> values)` that rejects a raw list of more than 100 entries with a generic AuraHandledException before any work, then normalizes the input (trim, drop empties, upper-case every value for comparison in both modes, de-duplicate case-insensitively keeping the first occurrence as typed), rejects a mode outside the closed list {TRACKING_NUMBER, REFERENCE} or more than 10 values after normalization with a generic AuraHandledException, wraps any unexpected exception in the same generic AuraHandledException (X7), treats a tracking value not matching `^RC\d{9}$` or any value longer than 50 characters as "Not found" without querying it, and delegates the read to a small `without sharing` helper `PublicTrackingSelector` with a `// SECURITY-JUSTIFICATION:` comment that runs one bound query `WITH SYSTEM_MODE` selecting only Name, Customer_Reference__c and the BR-01 fields, with a static WHERE on Name or Customer_Reference__c (closed list, no dynamic SOQL), ORDER BY Name, LIMIT 51 (50 rows are returned; a 51st row means the cap was hit). Matching of found rows to typed values is case-insensitive in both modes. The response is a DTO with exactly the seven BR-01 properties per shipment (`trackingNumber, status, originCity, destinationCity, lastLocation, lastUpdate, estimatedDelivery`), `lastUpdate` formatted in America/Mexico_City as `yyyy-MM-dd HH:mm`, `estimatedDelivery` as ISO `yyyy-MM-dd`, plus `notFound` (the normalized values with no match, in input order) and `truncated` (true when the 50-row cap was hit; then no value is listed in notFound, because a cut-off value is not proven missing). The guest profile gets class access to PublicTrackingController only (C8); guest-access-check.sh gets an exact class allow-list. Discarded: guest object Read + guest sharing rule (P2); `cacheable=true` (P5); dynamic SOQL with the field chosen by the caller (P3); returning Shipment__c records (P3, X6); a separate "invalid format" message (P4: one "Not found" for every miss).
- S2 → P1: a public LWC `rcTracking` on the home page (replacing the rcHome placeholder in the home view, rcHome kept as the hero heading or merged — worker's choice within scope) with a mode choice (radio group: Tracking number / Order reference), a textarea for up to 10 values split on commas and line breaks, a client-side count check with the same rule as the server (trim, drop empties, de-duplicate case-insensitively, then more than 10 → "Enter up to 10 values" and no call), result cards (mobile first) with the seven fields, a "Not found" list, and a sort selector: Status (lifecycle order of the picklist) or Estimated delivery (ascending, empty dates last). Generic error text when the call fails; when `truncated` is true, "Showing the first 50 results. Narrow your search." Mobile first: one column below 768 px. Discarded: a data table (poor on mobile, the primary device); server-side sorting (10 values at most; no extra call).
- S3 → P6: fix the header: the full logo shows at least 360 px of visible logo at desktop widths (wider image box and/or a breakpoint where it fits), and the scopedHeaderAndFooter gray wrapper is removed through the theme (branding set or theme layout background) rather than per-component hacks; brand-check.sh checks both. Discarded: cropping the PNG stand-ins (A3: logos are used as delivered).
