## Findings while building (decisions inside the handoff)

1. **License defaults.** A new profile with only `<userLicense>Customer Community</userLicense>` got 33 ObjectPermissions rows from the platform: Account (Read, Edit), Contact (Read, Create, Edit), Case, Order, Contract, Asset, WorkOrder, Shipment, UserExternalCredential and 24 more (the same set as the standard "Customer Community User"). The check went red on them (output below). The profile file now revokes each of the 33 explicitly (all flags false), so the profile has **0 ObjectPermissions rows**. `LICENSE_DEFAULT_OBJECTS` in the check is therefore empty: any object permission on the profile is a violation.
2. **Two Network phases are real.** Deploying force-app's final Network while the profile was not a member was refused: `Error: You can only select profiles that are associated with the experience.` (deploy 0AfEk00000h5Lr3KAE). customer-owner.sh applies the member-only bootstrap first, then force-app's Network.
3. **Lower-case profile names.** The platform stores the profile name lower case in Network (`<profile>`, `<selfRegProfile>`) and in ProfilePasswordPolicy `<profile>` (like `admin`). The source files use `rutacargo customer`, so a retrieve equals source; the check matches the policy's profile case-insensitively.
4. **Default self-registration account** is not in Network metadata; it is the `NetworkSelfRegistration` object (AccountId, NetworkId). The check and customer-owner.sh require 0 rows for the network.
5. **Owner role, conservative choice (auto mode).** customer-owner.sh gives the role only when the owner has no role; it refuses to replace another role (the owner decides). It checks both site rows (RutaCargo and RutaCargo1, same owner) and fails if either has no owner or they differ.
6. **Source tracking.** The first network deploy reported 1 stale conflict. A retrieve showed the org's Network equal to HEAD except the platform-managed sender address (the unverified `noreply@example.com` is replaced by the org); `--ignore-conflicts` was used per the handoff. customer-owner.sh deploys from a temporary metadata folder, so tracking is not involved.
7. **Section 7 of guest-access-check.sh unchanged.** With self-registration on, SiteRegister and CommunitiesSelfReg still answer 401 to an anonymous GET; no update was needed (file not touched).
8. **Defect found and fixed before commit:** `query` was first called inside `$(...)`, so its `exit 3` ended only the subshell; an empty result could then pass a "0 rows" assertion (for example NetworkSelfRegistration). All three scripts now store the result in `ROWS` and call `query` directly; a failed query stops the script (proof below).
