## 2. Root cause

Not in CustomerRegistration. The owner saw "accountId parameter value is not valid" on a cached old page: the register view before T3 (19a2d9f) placed the standard `community_login:selfRegister`, whose action `applauncher.SelfRegisterController.selfRegisterGetRedirectUrl` calls `Site.createExternalUser` with an empty accountId (the component had no accountId property and the network has no default self-registration account) and shows the platform's message as text. The main session confirmed it with the owner: the owner then signed up successfully through the published SelfRegister route with the new rcSignUp form (section 4).

Supporting facts:
- rcSignUp → CustomerSignUpController cannot show that text: CustomerRegistration catches every createExternalUser exception and returns `FAILED` → `MESSAGE_FAILED`; a rejected call shows the generic text in rcSignUp.
- Routes checked anonymously (curl, following redirects): `/rutacargo/SelfRegister` 200 (the only route with routeType `self-register`, view `register`); its published module `/rutacargo/webruntime/view/bf63b12728c3af3ea3146ad00290cd03/prod/en-US/register_view` contains `c/rcSignUp` twice and no `community_login/selfRegister`; the HTML is `cache-control: max-age=0,must-revalidate,private` (a reload always gets the new view; an already open single-page tab keeps the old one). `/rutacargo/login` 200 (rcLogin, its "Sign up" link goes to `/rutacargo/SelfRegister`); `/rutacargovforcesite/login` 200 (the platform's login page; its only sign-up link `id="selfReg"` goes to `/rutacargo/SelfRegister?locale=us`). `/rutacargo/login/SelfRegister`, `/rutacargo/selfregister`, `/rutacargo/register`, `/rutacargo/s/login/SelfRegister`, `/rutacargo/s/SelfRegister`, `/rutacargo/s/register`, `/rutacargo/CommunitiesSelfReg` → 404; `/rutacargovforcesite/CommunitiesSelfReg`, `/SiteRegister`, `/MicrobatchSelfReg`, `/apex/CommunitiesSelfReg`, `/s/login/SelfRegister` → 401 (guest page access disabled). In source, rcHeader and rcLogin link to `${BASE_PATH}/SelfRegister`. No route or link leads to a standard self-register form.
- The standard action is still callable by the guest at the Apex endpoint (T3 access review guardrail): called once with accountId "" under the guest trace it answered `Your request cannot be processed at this time.
