## Root cause (why the old check 11 was a false green)

The published layout bundle (`/rutacargo/webruntime/view/.../scopedHeaderAndFooter_view`, read anonymously) shows that:
- `community_byo/scopedHeaderAndFooter` hard-codes the gray in its own stylesheet, with no styling hook:
  `.community_byo-scoped-header-and-footer__header-content {background-color: rgb(239, 240, 242);max-width: var(--dxp-c-header-content-max-width);margin: 0 auto;}` (the footer content wrapper is the same).
- `community_layout/section` sets `--dxp-c-section-image-overlay-color` (the `backgroundImageOverlay` attribute) only inside `setComputedCssVariables()`, and only when `backgroundImageConfig` has desktop, tablet and mobile image URLs. Our sections have `backgroundImageConfig: ""`, so the `#0D1F5F` overlay was never painted. The section padding (`--dxp-s-section-content-spacing-*` = the branding set's Horizontal/VerticalRowPadding, 1rem desktop and 0.75rem mobile) therefore showed the gray. It formed a 16 px ring around rcHeader and a 32 px band for the empty footer.
- The theme cannot recolor the wrapper. A palette color can only be painted through a section background image plus overlay, and that needs an image asset. So the fix removes the area where the wrapper shows: the branding set row paddings are now `0rem`. The header wrapper is then covered edge to edge by rcHeader (night blue `#0D1F5F` box), and the empty footer section has no height. A per-component hack was not used.
