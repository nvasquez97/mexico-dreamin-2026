### Finding 1 (task-reviewer, Medium): test setup consumes the org's only Integration license - fixed

- `TestDataFactory.newOrExistingIntegrationUser(key)` replaces `newIntegrationUser`. It returns the SAVED active user with profile "Minimum Access - API Only Integrations" that holds `SalesforceAPIIntegrationPsl` (semi-join on PermissionSetLicenseAssign, `ORDER BY CreatedDate, Id LIMIT 1`). If there is none, it returns an UNSAVED new user. When the `@TestVisible reuseExistingIntegrationUserOnly` override is true, it throws `TestDataException` instead of building a user.
- EntregaYaAccessTest setup inserts the user and the PSL assignment only for a new user. It inserts the permission set assignment and the group membership only when they are missing. Test methods find the integration user through its group membership, independently of the factory's lookup.
- Create path, in this org: no integration user exists (`UserLicense Salesforce Integration: TotalLicenses 1, UsedLicenses 0`; `SELECT COUNT() FROM User WHERE Profile.Name='Minimum Access - API Only Integrations'` = 0, before and after the runs). The setup therefore took the create branch, and all 27 LOOP tests pass on it.
- Reuse path: `factory_reusesTheExistingIntegrationUser` sets the override, calls the factory with two keys (`rceyone`, `rceytwo`), and asserts that both return the setup's integration user. No real integration user was created in the org; that is T4's job.
- Red before the fix (factory without reuse, `existing.clear()` temporarily, run 707Ek00003UyGAr):
  `EntregaYaAccessTest.factory_reusesTheExistingIntegrationUser  Fail  TestDataFactory.TestDataException: No active Minimum Access - API Only Integrations user holds SalesforceAPIIntegrationPsl` (Pass Rate 96%)
- Green: run 707Ek00003UyU5Y, 27/27. Final tree: run 707Ek00003UycUN, 27/27.

  - When the T4 user is reused, the test's FLS/permission assertions run as that real user. Any extra permission that T4 gives it would turn them red, which is intended.
