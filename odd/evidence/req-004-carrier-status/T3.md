### Skill conflict (the handoff and X7 won)
The skill's REST template (platform-apex-generate assets/rest-resource.cls) puts exception text in the response: `handleError(res, 400, 'Malformed JSON: ' + e.getMessage())`, `handleError(res, 500, e.getMessage())`, `e.getDmlMessage(0)` and `saveResult.getErrors()[0].getMessage()`. It also maps the body with `JSON.deserialize` straight into a record. The resource does not follow it. Error bodies carry only a closed code and the service's fixed message, built with `JSON.serialize` of a Map (X7). The body is read with `JSON.deserializeUntyped`, and only the five contract keys go into EntregaYaStatusRequest, never an SObject (X6). The template's `ApiResponse` envelope (success/message/data) is not used either: D2 decides the body shapes.

## Design notes
- Order of work: (1) `FeatureManagement.checkPermission('RutaCargo_EntregaYa_Sender')`, otherwise 403 FORBIDDEN before anything is read; (2) parse; (3) `EntregaYaStatusService.apply`; (4) map the outcome. The whole `handle()` runs inside one try/catch(Exception), and any escaping exception answers 500 INTERNAL_ERROR with the service's fixed message.
- These answer INVALID_JSON: a null or empty body, invalid JSON, bytes that are not UTF-8 (StringException), a JSON value that is not an object (array, string, null), and a known key holding a number, boolean, array or object. Unknown keys are ignored. Keys are case-sensitive, so a miscased key counts as missing (MISSING_FIELD).
- `JSON.serialize` of a Map does not keep key order (observed: `{"error":{"message":...,"code":...}}`). Tests parse the bodies and compare them whole, with the keys sorted.
- Governor limits: 1 SOQL and 1 DML per call (the service's); the resource adds none. One POST is one change, so no collection is processed. The 251-record bulk rule does not apply to the resource; the trigger's bulk behavior is covered by T2.
- Test fix during the loop: the first LOOP runs with all three classes failed in setup with `UNABLE_TO_LOCK_ROW` on the User insert (TestDataFactory.insertSupportAgent). The new test used the same agent key `rceyagt` as EntregaYaAccessTest, so the two parallel setups inserted the same username. The key is now `rceyrag`; the runs after that were green.
