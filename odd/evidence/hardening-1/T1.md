## What changed
- `RecipientAccess.verifyBeforeCallout`: for an existing shipment the pair key is `shipmentId + ":" + hex SHA-256(normalizedPostalCode(typed) ?? "")` (`pairKeyOf`); the pair's existing row is read `FOR UPDATE` (`lockPairGuard`) before the lock check and the code comparison; the lock checked is the pair's; every failure for an existing shipment is counted on the typed pair (`countFailure(shipmentId, key)`), whatever the postal code; success makes no DML; `resetAttempts` resets the verified pair (key kept in a private field of Verification, never returned). One `DeliveryAccessCode.matches` per non-locked path, unchanged messages. Unknown tracking numbers: no key, no guard (intended).
- Seams: `@TestVisible nowOverride` (clock) and `@TestVisible trace` (step names only: `pairReadForUpdate:row|none`, `codeCompared`, `failureCounted`; never a key, hash or typed value).
- `Shipment_Key__c` Text(100) (83 used), unique, external Id, case-sensitive; descriptions of the object and its four fields describe one guard per pair. `scripts/checks/schema-check.sh` asserts Text 100.
- `RecipientDeliveryController`: header comment only (per-pair rule; the success path reads the pair FOR UPDATE, which is not DML). SECURITY-JUSTIFICATION of RecipientAccess rewritten for the per-pair rule, approver "(pending owner approval, 2026-11-18)".
- Tests: `TestDataFactory.recipientAccessGuardKey` computes the key independently (own normalization and digest) and `newRecipientAccessGuard(shipmentId, typedPostalCode, failedAttempts, lockedUntil)` replaces the per-shipment builder. `shouldNotCount_WhenPostalCodeIsWrong` (old rule) was removed: AC-H1.1/AC-H1.2 replace it with the opposite rule.
