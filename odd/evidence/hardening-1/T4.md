## Design

- `secret-scan.sh --staged` reads the paths staged for the commit (`git diff --cached --diff-filter=ACMRT`) and scans their content in the index (`git grep --cached`). `--tree` scans every tracked file at HEAD (`git grep ... HEAD`). Exit codes: 0 clean, 1 findings, 2 usage or git error.
- Rules: ENTREGAYA-KEY-SHAPE, PEM-PRIVATE-KEY, SFDX-AUTH-URL and SECRET-ASSIGNMENT (quoted literals of 8 or more characters, or XML elements, for consumerSecret, clientSecret, password, api key, private key, access/refresh/auth token and secret names; references and placeholders are excluded by their value).
- Output is `file:line RULE` only. The matched content stays in a temporary work directory, which is deleted on exit, and is never printed.
- Key shape (H6): two lowercase letters, `_`, two lowercase letters, `_`, four lowercase letters, `_`, then 20 or more letters or digits. The script builds the pattern from character classes (`L='[a-z]'`, then `${L}{2}_${L}{2}_${L}{4}_[A-Za-z0-9]{20,}`), so it contains no prefix text and does not match its own source.
  - How I got the shape without exposing the value: I read line 182 of `docs/functional-design.md` at b85773a and immediately reduced it to a character-class run signature (`a{2} _{1} a{2} _{1} a{4} _{1}` followed by 20 mixed `9/A/a` classes, 31 in total). Only that signature was printed. The value was never printed, copied or searched for.
  - Effectiveness check, again without printing the value: the shape pattern run over that historic blob prints only the line number, `182`. The rule therefore matches the leaked key.
- Allow-list: the `ALLOW_PATHS` mechanism is path-only and limited to pattern-definition files under `.claude/skills/sf-security-audit/`. It is empty, because none is needed: the whole tracked tree, including that tooling, this script and the self-test, scans clean.
- Hook: `.husky/pre-commit` runs `npm run precommit` (lint-staged) first, then `bash scripts/checks/secret-scan.sh --staged`, so the scan sees the content as lint-staged formatted it. Husky runs the hook with `sh -e`, so a failure of either step refuses the commit. `core.hooksPath` was not set by hand.
- Limits, also documented in the script: binary files are skipped (`-I`), and unquoted `key=value` literals are not reported because in code they are almost always variable names.

### Findings

1. **security-reviewer Medium CODE-001 (X14/P2), the scan misses secret kinds: fixed.** New and widened rules, all applied in a perl filter after a coarse `git grep -i` (one call per pattern):
   - SECRET-ASSIGNMENT XML: any element whose name ends in secret, password, token, api key or private key. This covers legacy Named Credential `<oauthToken>` and `<oauthRefreshToken>` and attributes such as `xsi:type`.
   - SECRET-ASSIGNMENT Custom Metadata: when a `<field>` ends in Key, Secret, Token or Password (`Api_Key__c`), its `<value>` on the same or a later line is checked. The finding names the value's line.
   - SECRET-ASSIGNMENT unquoted: `KEY=v` and `key: v`, in configuration files only (`.env*`, `*.yml`, `*.yaml`, `*.properties`, `*.ini`, `*.cfg`, `*.conf`, `*.toml`).
   - SECRET-ASSIGNMENT for names that only end in a secret word (`"token": "v"`, `oauthToken = 'v'`): reported when the literal looks generated (a digit, or upper and lower case). Header setters (`setHeader` / `header` / `set` / `append` / `put` with a header name such as `x-api-key`) take any literal.
   - BEARER-TOKEN: `Bearer <16+ token characters>`, and `Basic <base64>` on an Authorization line. `Bearer {!$Credential.Password}` (ProofOfDeliveryService) and `'Bearer ' + key` are not values. The self-test proves both are accepted.
   - JWT (three base64url segments, the first two starting `eyJ`) and SF-ACCESS-TOKEN (org id, `!`, token).
   - `$`-leading passwords: a value counts as a reference only when it is `${..}`, `$(..)`, `$UPPER_CASE_VAR`, `{..}`, `%VAR%` or holds `<`/`>`. A literal such as `'$' + letters/digits` is now reported. The old rule skipped every value starting with `$ % { < @ (`.
   - SECRET-FILE and the `.gitignore` globs: see finding 3.
2. **security-reviewer Low CODE-002, staged paths with a tab or newline are not scanned: fixed.** The staged list (`git diff --cached -z`) and the grep output (`git grep -z`) stay NUL-delimited and are parsed by perl as `path NUL line NUL content LF`. The parse is unambiguous: a path has no NUL, and a text line has neither NUL (`-I`) nor LF. A tab or newline in a path is printed escaped (`\t`, `\n`), so one finding stays one line. There is no TSV join anymore.
3. **security-reviewer Low CODE-003 and access-auditor Low, binary keystores pass and .gitignore lacks the globs: fixed.**
   - New rule SECRET-FILE, reported at line 0 (the whole file), binary included. It matches `.env` and `.env.*` (except `.env.example`, `.sample`, `.template` and `.dist`, which are content-scanned), and `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.key`, `*.p8` and `id_rsa`/`id_dsa`/`id_ecdsa`/`id_ed25519`. In `--tree` mode the path list comes from `git ls-tree -r -z`.
   - `.gitignore` now ignores `.env.*` (with `!.env.example`/`.sample`/`.template`/`.dist`), `*.key`, `*.pem`, `*.p8`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore` and `id_*` keys. `git ls-files -ci --exclude-standard` is empty, so no tracked file becomes ignored. `git check-ignore -v` confirms `.env.local`, `server.key` and `a/b.p12` are ignored and `.env.example` is not.
4. **task-reviewer Low test-quality, no near-miss negatives and one positive per rule: fixed.**
   - Second positives: a 27-character key tail, an OPENSSH header, and an SFDX URL in the refresh-token form.
   - Accepted near misses, each committed through the hook: a 19-character key tail, PUBLIC KEY and CERTIFICATE headers, `force://` with no credentials, a Bearer merge field and a variable, `$UPPER` and `${..}` references, a `.env.example` with placeholders, a Custom Metadata value of a non-key field, and YAML names that only start with `token`.
