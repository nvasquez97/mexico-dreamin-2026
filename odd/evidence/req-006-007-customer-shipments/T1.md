## Does the sharing set take effect inside an Apex test? Yes (A10 does not repeat)

This was proven in three steps against the same test class:
1. No grants: the user-mode query throws `sObject type 'Shipment__c' is not supported` (red 1).
2. Permission set only (Read and FLS deployed, no sharing set): `anaReadsEveryShipmentOfHerAccount` and `martaReadsEveryShipmentOfHerAccount` are red. The customer has object Read but sees none of her own 251 shipments (red 2).
3. Sharing set deployed: all 7 green, and each user reads exactly the 251 shipments of her account and none of the other's.

So, unlike the criteria sharing rules of A10, the sharing set is evaluated inside a test under `System.runAs`, and the Apex test is a real proof. No Manual-share mirror was needed. That is also impossible for these users: Customer Community users are high-volume users and cannot be the target of share rows. Mutation 2 confirms this from the other side: removing the profile from the sharing set turns the Apex own-read tests red as well as the live check.
