## What was built

- Branding set `Build_Your_Own_LWR` (APP). Color roles: primary
  PrimaryAccentColor #016BFA with #FFFFFF text, text TextColor #0D1F5F,
  background #FFFFFF, neutral and root-1 #D6E0EA, info #0D1F5F. The accents are
  used only for feedback: warning #FFC91D (black text) and destructive #FF3636
  (black text). Darker tones follow the Rule of 3. Typography: BaseFont
  Montserrat, XL and L headings 900 uppercase, M/S/XS headings 700, labels 500,
  small body 300, buttons 700. WCAG contrast of every pair set (all at least
  4.5:1): primary/white 4.68, primary-1/white 6.49, text/white 15.24,
  text/#D6E0EA 11.40, neutral-3/white 5.14, warning/black 13.62, destructive/black
  5.83, destructive-1/white 5.03, white on night blue 15.24, cyan on night blue 10.15.
- rcMontserrat static resource: Montserrat[wght].ttf (renamed
  Montserrat-wght.ttf) and OFL.txt, fetched over HTTPS from
  github.com/google/fonts ofl/montserrat at commit
  8b0a1d0f5983c89bc2b93f1b5fb55f9e252744b5. sha256 of the TTF
  0f7b311b2f3279e4eef9b2f968bcdbab6e28f4daeb1f049f4f278a902bcd82f7, of OFL.txt
  8b7141c03fa4f8d44e6345d5d4931709290f0f67875e452e95ac1fd3a027802e. It also holds
  montserrat.css, which declares the @font-face with a URL relative to the
  stylesheet. rcHeader loads it with `loadStyle`, because a component
  stylesheet cannot declare @font-face (shadow DOM ignores it). No woff2 tool
  was available, so only the TTF is shipped.
- rcBrandLogos static resource: the six PNGs of docs/brand. Both resources are
  cacheControl Public, in folder source form (contentType application/zip).
- rcHeader (theme layout scopedHeaderAndFooter, header region, new component id
  605e53b7-8ff0-4075-821e-c5d33821beec): logo-negative.png on night blue
  #0D1F5F, alt "RutaCargo", logo link and a "Track" link to `basePath + "/"`,
  `<nav aria-label="Main">`. The theme layout already renders `<header>`,
  `<main role="main">`, `<footer>` and a skip link (verified in the published
  scopedHeaderAndFooter module), so rcHeader adds only `<nav>` and rcHome only
  a `<section aria-labelledby>`. This avoids duplicate banner and main landmarks.
- rcHome (home view, replaces the template's htmlEditor placeholder, new
  component id 469ca6fa-0583-462d-9f21-c33ac60312de): hero with h1 "Track your
  shipment" and a short text, on `var(--dxp-g-brand, #016bfa)`. No Apex, no data.
- The new UUIDs come from `crypto.randomUUID()` and are unique in the bundle.
  The existing ids were kept.
- scripts/checks/brand-check.sh: see its header for the 8 rule groups. It
  runs source checks (role values, palette, logo and background pairs, alt
  text, the font face in the resource loaded by the header, external hosts,
  Daily Brew, cacheControl), org checks (CSP trusted sites, StaticResource
  CacheControl) and anonymous GETs (the published home page carries
  `--dxp-g-brand:#016BFA` and loads no external font; the logo, the font
  stylesheet and the font through the site URL). The host comes from DomainSite.

Decisions and deviations made during the task:

1. The branding set rejects commas in BaseFont. The deploy error, verbatim:
   `property: BaseFont, the property value: Montserrat, Arial, sans-serif,
   contains a disallowed character. Allowed characters are: a-z A-Z (space) - _ ' " .`
   So BaseFont is `Montserrat` alone, and `font-display: swap` shows the
   browser's default font while the TTF loads.
2. The @font-face first lived in the site's styles.css
   (sfdc_cms__styles/styles_css). The deploy stored it (a retrieve from the org
   showed the new CSS), but after three `sf community publish` runs the
   published `/rutacargo/assets/styles/styles.css?<versionKey>` kept serving the
   template file (same etag "fa42006783", `x-sfdc-edge-cache: none`; the publish
   jobs 08PEk00000qQl2CMAS, 08PEk00000qQh6eMAC and 08PEk00000qQHQrMAO were all
   Complete). The @font-face therefore moved into the rcMontserrat resource and
   is loaded by rcHeader ("in the theme or the header component", as AC-F.10
   says). styles.css was reverted to its original, and the reverted content was
   redeployed, so the org and the source agree.
3. The site's global link rule `a:link:not(.slds-button, .slds-dropdown__item > a)`
   (specificity 0,2,2) made the "Track" link brand blue on night blue: 3.3:1,
   which fails AA. This was seen in the 320 px probe. Fix: rcHeader sets the
   DXP link hooks `--dxp-c-link-text-color*` (white, cyan on hover/focus/active),
   which that rule reads first. Confirmed live: TRACK in white.

## Governor limits and performance

TTF is 745 KB (all weights). A woff2 or subset copy would be about 100 KB;
that needs fonttools or woff2 tooling, which this machine does not have.
